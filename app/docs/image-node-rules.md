# Visioner ImageNode 规则文档 v1

> 用途：作为 ImageNode 的 prompt 组装、API 接入、交互实现和兼容维护依据。  
> 基线：当前项目工作区实现。  
> 状态标记：**已实现**表示当前代码已具备；**规则合同**表示后续实现必须遵守；**已知缺口**表示当前数据或代码尚不能完整表达。

---

## 1. 总原则

ImageNode 以客户明确表达为核心：

> 用户显式意图 > 未修改的参考用途规则 > 系统辅助推断 > 系统默认 > 模型默认

判定优先级时，不能只看内容来自哪个模块，还要判断内容是否被用户主动写过、改过、选过或开启过。

1. 用户主动写入、修改、选择或开启的内容属于用户显式意图。
2. 用户显式意图高于系统默认与模型默认。
3. 系统默认只在用户没有明确表达对应维度时生效。
4. 局部标记只覆盖其局部范围，不应无故改变全局规则。
5. “未设置”和“跟随参考”不生成额外覆盖 prompt。

### 1.1 当前实现状态

- **已实现**：引用说明与标记说明通过 `promptTextEdited` 区分默认内容和用户修改内容。
- **已实现**：氛围控制器仅序列化非空选择和开启的开关。
- **已实现**：最终 prompt 包含用户显式意图、主体默认保护、局部标记优先等冲突说明。
- **已知缺口**：当前 TextNode 没有完整的“用户编写 / AI 生成 / AI 生成后被用户修改”来源字段。
- **已知缺口**：布尔开关的 `false` 同时表示默认关闭和用户主动关闭，当前不能区分两者。

## 2. 用户显式意图

以下内容属于用户显式意图：

1. ImageNode 内部用户手写提示词。
2. 用户直接编写的 TextNode 引入文本。
3. AI 生成后被用户修改过的 TextNode 文本。
4. 用户修改过的图像引用说明。
5. 用户修改过的标记说明。
6. 用户手动设置的时间、光线、天气和风格。
7. 用户主动开启的增加配景、增加人物、室内灯光和动态模糊。
8. 用户明确提出的建筑结构、体块、立面、入口、屋顶或材质修改。

用户显式意图优先于氛围参考、未修改参考说明、系统默认和模型默认。

### 2.1 显式意图的持久化

- 图像引用说明：`PromptContent.image_reference.promptTextEdited`。
- 标记说明：`PromptContent.image_mark_reference.promptTextEdited`。
- 氛围选择：`ImageControllerState` 中对应值非 `null`。
- 氛围开关：对应 toggle 为 `true` 时进入 prompt。
- ImageNode 手写文本：`ImageNodeData.prompt`。
- TextNode 文本：通过连接读取；当前没有来源/编辑状态元数据。

## 3. 系统默认

系统默认只在用户没有明确表达对应维度时生效，包括：

1. 主体建筑默认保护。
2. 氛围参考默认跟随。
3. 控制器未设置状态。
4. 模型默认审美与补全策略。

### 3.1 主体建筑默认保护

主体建筑参考默认保持以下关系稳定：

- 建筑结构。
- 体块比例。
- 立面关系。
- 相机角度。
- 构图比例。

主体建筑不是绝对硬约束。用户明确要求改变入口、立面、楼层、屋顶、体量或材质时，以用户显式意图为准。

当前默认说明为：

> 默认保护主体建筑，保持建筑结构、体块比例、立面关系、相机角度和构图比例稳定；如果用户明确要求调整，则以用户显式意图为准。

## 4. Prompt 组装规则

### 4.1 规范优先级

1. ImageNode 内部用户手写提示词。
2. 用户编写或修改过的 TextNode 文本。
3. 用户修改过的标记说明。
4. 用户修改过的图像引用说明。
5. 用户手动设置的氛围选择。
6. 用户主动开启的氛围开关。
7. 未修改但已有用途定义的参考规则。
8. AI 生成且未被用户修改的 TextNode 辅助描述。
9. 系统默认。
10. 模型默认。

局部标记在其标记范围内高于全局氛围控制和氛围参考。

### 4.2 当前组装入口

`buildPromptSubmission` 负责生成：

- `textPrompt`
- `referenceImages`
- `markReferences`
- `promptBlocks`
- `userPrompt`
- `presets`
- `globalStyle`
- `imageReferences`
- `controller`

当前文本段包括：

1. TextNode 引入文本与 ImageNode 手写文本。
2. 主体建筑默认保护。
3. 氛围、材质、景观、照明、室内、局部和未定义参考。
4. 元素标记参考。
5. 独立全局 style。
6. lightPreview 光影控制。
7. ImageController 控制片段。
8. 维度控制与最终优先级说明。

### 4.3 Structured inputRefs 一致性

- **已实现**：如果某个 `sourceNodeId` 存在图像引用块，`referenceImages[].promptText` 使用该引用块最终的 `block.promptText`。
- 没有引用块时，回退到 `getImageReferencePromptText(reference)`。
- 用户清空并保存的自定义说明也应视为最终说明，不应被默认说明覆盖。
- 主 `textPrompt` 和 structured `inputRefs.promptText` 必须表达同一份最终引用意图。

### 4.4 当前已知缺口

- TextNode 当前先被拼接到 ImageNode 文本之前，且没有来源级权重字段；后端接入时不能仅依赖字符串位置判断优先级。
- preset、独立 style、lightPreview 与所有参考类型尚未形成统一的机器可读优先级对象。
- API 应优先读取结构化来源和显式状态，而不是推测自然语言段落顺序。

## 5. ImageNode 内部提示词

1. ImageNode 内部手写提示词是目标节点的直接需求，优先级最高。
2. 与 TextNode、氛围控制、氛围参考或默认参考规则冲突时，以 ImageNode 手写提示词为准。
3. 明确要求修改建筑时，可以覆盖主体建筑默认保护。
4. 未明确要求修改建筑时，主体建筑默认保护继续生效。

示例：主体建筑参考默认保持主体稳定，但 ImageNode 写入“把入口改成通透玻璃盒子”，则允许修改入口。

---

## 6. TextNode 引入规则

### 6.1 用户直接编写

属于用户显式意图，高于未修改参考、系统默认和模型默认。

### 6.2 AI 生成且未修改

属于系统辅助推断：低于用户手写、手动控制、用户修改过的引用和标记，但高于普通模型默认。

### 6.3 AI 生成后被用户修改

升级为用户显式意图。

### 6.4 与 ImageNode 冲突

ImageNode 内部手写提示词优先。

### 6.5 当前实现状态

- **已实现**：连接到 ImageNode 的 TextNode 文本会进入生成 prompt。
- **已知缺口**：当前没有可靠字段区分 TextNode 是用户编写、AI 生成还是 AI 生成后被修改。
- 在补齐 provenance 字段前，API 不应假定所有 TextNode 文本都等价于用户显式意图。

## 7. 参考用途

当前主用途包括：

- 主体建筑。
- 氛围参考。
- 材质参考。
- 景观参考。
- 照明参考。
- 室内参考。
- 未设置参考用途。

局部参考及旧 role 保留兼容读取。

### 7.1 未修改说明

- 主体建筑：默认保护主体和构图关系。
- 氛围参考：参考时间、天气、色调、光影和情绪。
- 局部参考：仅控制指定局部内容。
- 未设置用途：低优先级中性视觉参考。

### 7.2 用户修改说明

1. 使用最终 `block.promptText`。
2. `promptTextEdited` 标记为 `true`。
3. 后续用途变化不得覆盖用户说明。
4. 清空说明后保存仍属于用户自定义。
5. 仅进入编辑后原样退出，不应误标为自定义。

### 7.3 用途变化同步

- 未手动编辑：用途变化时同步新用途的默认说明、标签和颜色。
- 已手动编辑：只同步标签和颜色，保留用户说明。

### 7.4 唯一性与数量

- 同一目标节点最多一个主体建筑参考。
- 同一目标节点最多一个氛围参考。
- 推荐引用数量不超过 4 张。
- 最大引用数量为 6 张。

### 7.5 当前已知限制

- 局部参考配置已存在，但当前主用途菜单尚未恢复局部参考新建入口。
- 用途同时存在节点级和边级写入语义，本版不调整该模型。

---

## 8. 氛围参考

氛围参考定义为：参考整体时间段、天气状态、色调、光影氛围和画面情绪。

优先级低于用户手写、用户修改过的 TextNode、引用说明、标记说明和手动氛围控制。

### 8.1 有氛围参考时

- 时间：跟随参考。
- 光线：跟随参考。
- 天气：跟随参考。
- 风格：未设置。

“跟随参考”的底层值仍为 `null`，不是新枚举值，也不生成额外覆盖 prompt。

### 8.2 手动覆盖

用户选择具体时间、光线或天气后，仅覆盖氛围参考的对应维度；未覆盖维度仍由氛围参考提供。

### 8.3 清除

- 有氛围参考：时间、光线、天气恢复“跟随参考”。
- 无氛围参考：恢复“未设置”。
- 风格：始终恢复“未设置”。

---

## 9. 氛围控制器

### 9.1 字段

选择项：

- 时间。
- 光线。
- 天气。
- 风格。

开关：

- 增加配景。
- 增加人物。
- 室内灯光。
- 动态模糊。

### 9.2 默认状态

- 四个开关全部关闭。
- 时间、光线、天气和风格均为 `null`。
- 有氛围参考时，时间、光线和天气仅在 UI 显示“跟随参考”。
- 不默认选择“照片般真实”；它只保留为用户可选风格。

### 9.3 Prompt 规则

- 只有具体选择和开启的开关进入 prompt。
- 用户手动选择高于氛围参考、系统默认和模型默认。
- 开关不会因为参考图内容自动开启。
- 当前隐藏的 `season` 不参与 UI 有效状态，也不进入最终 prompt。

### 9.4 光线字段

字段名：

- zh-CN：光线。
- en-US：Light。

选项顺序：

| ID | zh-CN | en-US |
| --- | --- | --- |
| `front_light` | 顺光 | Front Light |
| `back_light` | 逆光 | Backlight |
| `left_side_light` | 左侧光 | Left Light |
| `right_side_light` | 右侧光 | Right Light |
| `diffused_light` | 柔和天光 | Soft Skylight |

---

## 10. 标记

标记是局部对象或区域指令，不属于全局氛围控制。

### 10.1 规则

1. 标记不因氛围参考存在而禁用。
2. 标记不自动跟随氛围参考。
3. 标记只在局部范围覆盖全局规则。
4. 标记在局部范围内高于氛围控制、氛围参考、未修改参考和系统默认。
5. 全局开关关闭不代表禁止局部标记。
6. 全局开关开启时，标记可以对局部区域进行排除或修正。

示例：

- 增加人物关闭 + 标记“这里加几个人”：只在标记区域增加人物。
- 增加人物开启 + 标记“这里不要有人”：全局允许人物，但标记区域排除人物。
- 天气为雪天 + 标记“入口区域不要积雪”：整体保持雪天，入口区域保持干净。

### 10.2 数据与同步

- 源节点保存 `imageMarks`。
- 目标节点保存 `image_mark_reference` prompt block。
- 更换源图时清理不再匹配当前图片的标记及其引用块。
- 未修改标记说明时，切换候选项同步候选默认 prompt。
- 已修改标记说明时，切换候选项保留用户说明。
- 删除源标记时同步删除关联标记引用块。

## 11. 冲突处理

| 冲突 | 结果 |
| --- | --- |
| ImageNode 手写 vs 系统默认 | 手写优先 |
| ImageNode 手写明确改建筑 vs 主体默认保护 | 手写优先 |
| ImageNode 手写 vs 氛围控制 | 手写优先 |
| ImageNode 手写 vs 氛围参考 | 手写优先 |
| 用户修改引用说明 vs 用途默认说明 | 用户说明优先 |
| 用户修改标记说明 vs 候选默认说明 | 用户说明优先 |
| 标记 vs 氛围控制 | 标记区域内，标记优先 |
| 标记 vs 氛围参考 | 标记区域内，标记优先 |
| 手动氛围选择 vs 氛围参考 | 手动选择对应维度优先 |
| 未设置 | 不生成额外 prompt |
| 跟随参考 | 不生成额外覆盖 prompt |

## 12. 引用块 UI 与编辑规则

图像引用块和标记引用块使用统一交互：

1. 默认单行胶囊，长文本 truncate。
2. 点击后在原位置进入 textarea 编辑。
3. Enter 换行。
4. blur、Esc 或点击外部保存并退出。
5. 不显示保存/取消按钮，不使用弹窗。
6. 单行 textarea 高度 24px，与默认块基本等高。
7. 两行及以上高度 44px。
8. 超过两行后内部纵向滚动。
9. 编辑态隐藏删除按钮和缩略图预览。
10. 整块 hover 只轻微高亮并显示删除按钮。
11. 只有缩略图 hover 显示图片预览和用途/标记名称，不显示 promptText。

## 13. 氛围 UI 状态

### 13.1 下拉

- 菜单只显示具体选项，不显示“无”。
- 点击选项后立即选中并关闭。
- 当前项高亮并显示 check。
- 点击外部或 Esc 只关闭，不改变值。
- 已选字段显示清除按钮。
- 未设置使用暗灰；跟随参考使用中等灰；具体值使用亮文字。

### 13.2 开关

- 关闭：弱灰文字、边框和背景。
- 开启：紫色 Switch、紫色边框、弱紫背景和亮文字。
- 卡片或 Switch 都可切换，Switch 点击不得双触发。

### 13.3 氛围入口按钮

边框表示面板是否打开：

- 关闭：灰色边框。
- 打开：紫色边框。

填充表示是否存在用户氛围设置：

- 无设置：透明或极弱填充。
- 有设置：弱紫填充。

组合规则：

- 关闭 + 无设置：灰边框、极弱填充。
- 打开 + 无设置：紫边框、极弱填充。
- 关闭 + 有设置：灰边框、弱紫填充。
- 打开 + 有设置：紫边框、弱紫填充。

不显示紫色圆点；hover 只轻微提亮，不使用外发光。

### 13.4 Tooltip

- 无设置、无氛围参考：不显示。
- 有氛围参考、无手动设置：显示“跟随氛围参考”摘要。
- 有手动设置：显示已设置摘要。
- 面板打开：不显示。

## 14. 弹层定位

统一规则：

1. 默认向下弹出。
2. 下方空间不足时向上。
3. 左右越界时自动修正。
4. 距可视区域边缘至少 12px。
5. 上下空间不足时限制 `max-height`。
6. 弹层内部滚动，不把滚轮事件传给无限画布。
7. Portal 渲染到 `document.body` 或画布 overlay，不放回 React Flow transform 节点内部。
8. 打开期间持续读取 anchor rect，跟随画布平移、缩放和节点移动。
9. 使用 `nodrag / nopan / nowheel` 与事件拦截避免画布误操作。

适用范围：氛围面板、参考用途菜单、标记候选菜单、预设弹层、右键菜单及其他锚定下拉。

### 14.1 当前实现状态

- **已实现**：参考用途菜单持续跟踪锚点。
- **已实现**：氛围面板持续跟踪锚点。
- **已实现**：两类标记候选菜单持续跟踪锚点，并具有 viewport clamp、上下翻转和内部滚动。
- **部分实现**：预设、右键、快捷指令和 hover 预览仍由各组件维护，尚未抽成统一定位工具。

## 15. Processing 锁定

Processing 状态下禁止：

- 编辑提示词。
- 新增、删除或编辑引用块。
- 新增、删除或编辑标记。
- 修改参考用途。
- 修改氛围控制。
- 修改预设、风格、光影和模型参数。
- 重复生成。
- 执行顶部工具栏动作。

权限应统一来自 `createImageNodeViewModel`，避免不同入口自行判断。

当前控制面板的标记编辑权限已使用 `imageNodeViewModel.canEditMarks`。

## 16. 数据兼容

1. 不删除 legacy role。
2. 不删除旧字段。
3. `overall_reference` 兼容为氛围参考。
4. 植物、人物、天空、custom 等旧 role 兼容为局部参考。
5. `season` 字段保留兼容读取，但当前不参与：
   - 氛围 UI 有效状态。
   - `hasActiveImageController`。
   - 最终 prompt。
6. 不因本规则文档执行数据迁移。
7. 旧数据缺少引用 prompt block 时，structured inputRefs 回退到用途默认说明。
8. `promptTextEdited` 缺失按未编辑处理，以兼容旧数据。

## 17. Undo/Redo 与生成历史

- ImageNode 状态更新继续通过现有 `setNodes / setEdges` 路径完成。
- Undo/Redo 快照保存节点数据与边数据，并移除运行时回调。
- 生成历史保存最终 prompt、inputRefs、markRefs、controller、模型参数等。
- 当前单条 `GenerationHistoryItem` 不保存完整 `promptContent` 快照；不要假定生成历史可以独立恢复当时所有引用块编辑状态。
- 本规则不改变现有 Undo/Redo 和历史结构。

## 18. API 接入建议

API 至少应接收并区分：

- `userPrompt`
- TextNode 文本及未来的 provenance
- `referenceImages` 与最终 `promptText`
- `markReferences`
- `controller.state`
- `controller.promptFragments`
- `globalStyle`
- `presets`
- `lightPreview` 派生 prompt
- 最终合成的 `textPrompt`

建议：

1. 不要只提交一条无法追溯来源的纯文本。
2. 不要重新用用途默认说明覆盖 structured inputRefs 中的用户说明。
3. 不要把 `null` 的氛围字段解释成用户要求“无”；它表示未设置或 UI 上的跟随参考。
4. 不要让保留兼容的 `season` 进入当前生成控制。
5. 局部标记的空间范围与 prompt 必须成对提交。

## 19. 已知缺口与后续议题

以下内容不属于当前已完成实现：

1. TextNode 用户/AI 来源及 touched 状态。
2. 布尔氛围开关的“默认关闭”和“用户主动关闭”区分。
3. 局部参考主菜单入口。
4. 所有 prompt 来源的统一机器可读优先级对象。
5. i18n 全量覆盖及静态配置的运行时语言刷新。
6. 节点级与边级参考用途模型统一。
7. 完整 promptContent 的逐次生成历史快照。
8. 所有 Canvas Portal 的共享定位工具抽取。

新增实现前应先判断是否需要数据字段和迁移，避免通过 UI 文案隐式改变业务语义。

## 20. 最终一句话规则

> 客户主动写过、改过、选过或开启过的内容属于用户显式意图；用户显式意图优先于系统默认，未修改参考按用途参与默认推断，氛围参考提供默认气质，氛围控制负责主动全局覆盖，标记负责局部最高指令，系统与模型默认只在客户没有明确表达时生效。
